# Hugo 博客从零部署到Github推送上线

这个教程解决一件事：在 Windows 上从零搭建一个 Hugo 静态博客（hugo-book 主题），本地写作、推送到 GitHub 后自动构建部署，全程不碰服务器、不装 Node 等开发环境。做完你会得到三样东西：一个部署在 GitHub Pages 的个人博客；一套"改文章 → 双击脚本 → 等一两分钟 → 网站自动更新"的日常流程；以及顺手的 git 使用与备份技能。

适用对象：Windows 用户，主要存放个人文章。不需要评论、访问统计等附加功能——静态站的特点是这些功能想加随时加，不用迁移任何数据。不会命令行也没关系，问 AI 即可（见"环境准备"）。

## 🎯 一、为什么用 Hugo

### ⚖️ 框架取舍

我最初研究搭建博客时被 B 站上大量的框架教程弄到信息过载。整理后确认两件事：
- 框架虽多，底层概念约八成都通用——Markdown 写作、Front Matter 元信息、主题配置、Git 部署
- 选型用排除法：先确认需求是"个人博客"而不是"文档站"；再看环境底线——我不想装 Node.js / Ruby 任何开发环境，这一步只剩 Hugo 和 Zola 满足；最后看折腾意愿——想开箱即用、跟着教程走

结论：选 Hugo。它是 Go 写的单文件程序，下载即用、构建速度同类最快、免环境，适合长期主义。其他框架各有一句话的理由不选：Hexo 是中文圈教程之王但要装 Node 环境；Jekyll 在 Windows 上装 Ruby 是出了名的痛；Astro 自由度太高容易迷失；Next.js 做博客是过度设计。就算以后想换框架，底层概念通用，换框架成本大约一个周末。

## 🧰 二、环境准备

### 📋 工具清单

- GitHub 账号（[github.com](https://github.com) 注册，免费，邮箱验证即可）
- Git for Windows（[git-scm.com/downloads](https://git-scm.com/downloads)，一路默认下一步）
- Hugo（[gohugo.io/installation](https://gohugo.io/installation/) 有各平台安装说明，见下）
- 编辑器：VS Code（[code.visualstudio.com](https://code.visualstudio.com/)）或记事本
- LLM 咨询（我用 [DeepSeek API](https://platform.deepseek.com/) + [Chatbox](https://chatboxai.app/) 前端）：细节不懂就问，理论上任意模型都行；搭配工作模式的本地读写能力，有些文件甚至可以直接让 AI 替我生成或改动

### ⌨️ 命令行

很多自部署项目（比如 Hugo 建站）是没有图形界面的，只能通过命令行操作，这跟我们习惯的"鼠标点击、拖拽"不太一样。这一点需要先接受：命令行是必经之路。不过 AI 普及把技术门槛降得很低——不会的、不懂的，问 AI 即可。后续所有步骤（排错、脚本编写）都是在这个工作方式下完成的：把问题发给 AI，AI 读取本地文件、定位问题、修改完善，再交回验证。

### ✅ 安装验证

安装 Hugo 二选一：
- 命令行（推荐）：`winget install Hugo.Hugo.Extended`
- 手动：到 [Hugo 官方 releases 页面](https://github.com/gohugoio/hugo/releases) 下载 `hugo_extended_..._windows-amd64.zip`（认准 extended 版本，部分主题需要），解压出 hugo.exe 放进固定文件夹并加入系统 PATH

验证：运行 `hugo version`，能输出版本号就成功。注意：hugo-book 主题要求 Hugo v0.158 及以上（我装的是 v0.161），低于此版本先 `winget upgrade Hugo.Hugo.Extended`。

## 🏗️ 三、建站与主题

### 🆕 新建站点

以下命令按顺序执行，每条后面跟着说明：

```
hugo new site myblog
```

`hugo new site` 是新建站点的命令，后面的 `myblog` 是项目文件夹名称，可以随意自定义（路径无中文即可）。我实际用的名字是 `Lt-Dr-website`。

```
cd myblog
```

进入站点文件夹——之后所有命令都要在这个目录里执行，否则找不到站点。

```
git init
```

初始化 git 仓库，让 git 开始记录这个项目的每一次改动，为后面的版本管理和部署做准备。

### 🎨 安装主题

先给通用方法：所有 Hugo 主题的安装方式都一样，把主题的 GitHub 仓库地址装进 themes/ 目录，然后在 hugo.toml 里声明启用：

```
git submodule add <主题的GitHub仓库地址> themes/<主题名>
```

用 submodule 方式安装，主题会作为独立子模块被记录，推送到 GitHub 后部署时能自动拉取（见"部署上线"）。安装完在 hugo.toml 里加 `theme = "<主题名>"` 即可。

我安装的是 [hugo-book](https://github.com/alex-shpak/hugo-book)（"书/文档"风格：左侧目录树、右侧章节导航、首页即封面加目录，契合"个人文章仓库"的定位），对应命令：

```
git submodule add https://github.com/alex-shpak/hugo-book themes/book
```

然后在 hugo.toml 里加 `theme = "book"`。

注意：主题以 submodule 形式安装，本地提交时别手动删掉 themes/book，否则部署会失败。

### ⚙️ 基础配置

打开站点根目录的 hugo.toml（新版 Hugo 的配置文件；旧教程里的 config.toml 是同一个东西），用记事本或 VS Code 编辑，改成：

```
baseURL = "https://你的用户名.github.io/"   # 先随便填，部署时再改
locale = "zh-cn"
title = "梦生的博客"
theme = "book"

[params]
  BookTheme = "auto"      # light / dark / auto（跟随系统）
  BookSearch = true       # 站内搜索（默认开启）
  BookSection = "docs"    # 侧边栏显示哪个栏目（默认 docs）
```

一个容易踩的坑：`locale` 是新版 Hugo（v0.158 起）的写法，旧教程里的 `languageCode` 已废弃。构建日志里出现的 `[en v1.0.0 guest]` 只是 Hugo 内部"语言键"的标签，与语言是否生效无关——我实测过，渲染出的页面是 `<html lang="zh-cn">`，配置确实生效。

## 📁 四、内容组织

> 说明：这一节以 hugo-book 主题为例。如果你安装的是其他主题，目录结构和参数名可能不同，把需求描述给 AI 让它按你的主题给出具体做法即可；通用的部分只有一条——文章就是 Markdown 文本文件，放在 content/ 目录下，用记事本或 Obsidian 编辑。

### 🗂️ 目录规划

hugo-book 的内容按两种方式组织：
- content/docs/：按主题分类的"书目录"，每个分组一个文件夹，最贴合这个主题的气质（我用的这种）
- content/posts/：按时间倒序排列的日记式博客

关键规则：每个分组文件夹里必须有一个 _index.md，它决定分组在侧边栏怎么显示。普通文章页可用的 front matter 参数：weight（排序，越小越靠前）、bookToC（false 关闭右侧目录）、bookComments（false 关闭评论）、bookSearchExclude（true 不参与搜索）、tags。

### 🧱 板块搭建

我搭了四个板块：知识分享、游戏攻略、哲学探讨、资源分享。PowerShell 在站点根目录一次性创建：

```
$i = 1
foreach ($d in @("知识分享", "游戏攻略", "哲学探讨", "资源分享")) {
  New-Item -ItemType Directory -Force -Path "content\docs\$d" | Out-Null
  @"
---
title: "$d"
weight: $i
bookCollapseSection: true
---
"@ | Set-Content -Encoding UTF8 "content\docs\$d\_index.md"
  $i++
}
```

运行完刷新 localhost:1313，左侧应出现四个可折叠板块，顺序由 weight 从 1 到 4 控制。

两个实测验证过的认知：
- 文件夹名只影响 URL，且会被 Hugo 清洗——`01.知识分享` 生成的 URL 是 `/docs/知识分享/`，数字前缀和 emoji 都会被去掉。所以文件夹随便加序号，纯粹为本地看着方便，手写链接不受影响
- 侧边栏排序看 _index.md 里的 weight，与文件夹名无关。保持"文件夹序号 = weight 值"一一对应，两边都不会乱

### ✍️ 写作预览

写文章两种方式：
- 手动新建：在板块文件夹里直接建 .md 文件，front matter 写 title、date、draft: false、tags
- 命令行：`hugo new docs/游戏攻略/文章名.md`（注意：hugo new 生成的文件自带 draft: true，记得改成 false，否则不会发布）

文章内容用 Markdown 书写——一种轻量标记语言，用少量符号（# 标题、**加粗**、[文字](链接)）给纯文本排版，Hugo 和 Obsidian 都原生支持，几分钟就能学会：[Markdown 语法速查](https://markdown.com.cn/basic-syntax/)。

编辑工具我推荐 [Obsidian](https://obsidian.md/)（免费，官网直接下载）：本地 Markdown 笔记软件，编辑 .md 文件所见即所得，写完复制到博客文件夹即可。它和我平时的笔记系统同源，写稿顺手。不想装软件的话，VS Code 或记事本也行——Markdown 本质就是纯文本。

注意：Obsidian 的部分扩展语法（双链、内嵌图片等）Hugo 不认，需要转换，见"笔记适配"一节。

本地预览：`hugo server -D`，浏览器打开 http://localhost:1313/（-D 表示连草稿一起显示，改文件保存后自动刷新）。

## ✨ 五、样式与兼容

> 说明：这一节同样以 hugo-book 为例。如果你是其他主题，改动方式和参数名会不一样，把需求描述给 AI 让它给出具体做法；需要理解的核心概念只有两个——Markdown 语法（文章怎么写）和 CSS 语法（网页长什么样），细节问 AI 即可。

### 📑 目录深度

hugo-book 的右侧目录用的是 Hugo 内置 TOC，默认只收录 h2~h3。我在 Obsidian 里习惯用五级标题，h4、h5 在正文正常渲染但进不了目录。在 hugo.toml 顶层（不要放进 [params] 里）加：

```
[markup.tableOfContents]
startLevel = 2
endLevel = 5
```

startLevel = 2 表示从 h2 开始收录（h1 一般是页面标题），endLevel = 5 收录到 h5。这是全站设置；某篇文章不想显示目录，在它的 front matter 加 `bookToC: false` 单独关闭。

### 🔤 标题加粗

hugo-book 的标题默认 `font-weight: inherit`，直接继承正文字重（400，常规粗细），完全不加粗，而且 h5 与正文字号相同（1rem），对比不明显。解决方式是往页面注入一段 CSS——CSS 是控制网页外观的语言（字体、颜色、大小、间距都归它管），下面这段只用了两个属性：

- 选择器 `.markdown h1 ~ h6`：限定作用范围，含义是"正文区域（.markdown）里的所有标题"，侧边栏、目录、搜索框的样式不受波及
- `font-weight: 700`：字重，400 是常规、700 是加粗——把标题统一加粗
- `font-size: 2.1rem` 等：字号，rem 是相对单位，2.1rem 约等于默认字号的 2.1 倍——给各级标题拉开大小层级，数字越大标题越大

注入位置：主题留了官方样式注入点——在站点根目录创建 `layouts/_partials/docs/inject/head.html`（注意是 _partials，主题新版结构如此；该文件在主题里是空的，专门留给用户覆盖），粘贴：

```
<style>
  .markdown h1,
  .markdown h2,
  .markdown h3,
  .markdown h4,
  .markdown h5,
  .markdown h6 {
    font-weight: 700;
    line-height: 1.4;
  }
  .markdown h1 { font-size: 2.1rem; }
  .markdown h2 { font-size: 1.65rem; }
  .markdown h3 { font-size: 1.35rem; }
  .markdown h4 { font-size: 1.15rem; }
  .markdown h5 { font-size: 1.05rem; }
  .markdown h6 { font-size: 0.95rem; }
</style>
```

保存后 Hugo 会自动重建，刷新即见效果。以后样式多了，可以把内容挪到 static/css/custom.css，head.html 只留一行 link 引入，方便长期维护。

### 🔗 笔记适配

直接把 Obsidian 笔记搬进 Hugo 有一个大坑：Obsidian 的 Markdown 是"超集"，Hugo 只认标准 Markdown。需要转换的语法：

| Obsidian 语法 | Hugo 里的表现 | 修复方法 |
|---|---|---|
| 双链 [[笔记名]] | 原样显示成文本 | 改成 [笔记名](链接) |
| 图片嵌入 ![[xxx.png]] | 乱码/不显示 | 图片放 static/images/，改成 ![](/images/xxx.png) |
| 高亮 ==文字== | 原样显示 | 改成 **文字** |
| 行内标签 #标签 | 原样显示 | 删掉，改用 front matter 的 tags: |
| 引用块 > [!note] | 变普通引用还带字样 | 改回普通 > 引用 |

好消息：
- Front Matter 基本兼容——Obsidian 顶部的 created、aliases 等属性 Hugo 直接忽略，tags: ["xxx"] 格式能识别
- 日期不用写——Hugo 会用文件修改时间当文章日期，排序不乱

工作流建议：Obsidian 当"笔记母本"，博客放"精选副本"——粘贴时挑一挑、顺手改语法、图片单独处理。笔记多了以后可考虑批量转换工具【此为推测：第三方工具更新频率不定，真要用时需再查现状】。

## 🚀 六、部署上线

部署方案我选的是 GitHub Pages——GitHub 官方的免费静态托管服务。工作方式是：本地推源码到 GitHub 仓库 → GitHub Actions 自动跑 Hugo 构建 → 生成的静态文件发布到 Pages 网址。好处：零成本、和 GitHub 账号一体、稳定，Hugo 社区资料最多，以后想接评论（Giscus）也方便——评论数据存在同一个 GitHub 账号下。

### 📛 仓库命名

GitHub Pages 有两种站点：
- 用户站：仓库名必须等于 `用户名.github.io`，网址是根路径 `https://用户名.github.io/`，一个账号只有一个
- 项目站：任意仓库名，网址带子路径 `https://用户名.github.io/仓库名/`

我最初建错成 `littledream.github.io`，后来在网页端重命名成 `790192412-ux.github.io` 才匹配。关键原因：博客里的手写链接是根路径（/docs/知识分享/），只有用户站能全部原样生效；项目站会导致链接全部 404。所以直接建 `用户名.github.io` 仓库，一劳永逸。

### 📄 配置准备

两个配置文件放进站点根目录。

.gitignore（忽略构建产物与脚本）：

```
public/
resources/_gen/
.hugo_build.lock
*.bat
.DS_Store
Thumbs.db
*.log
.idea/
.vscode/
```

.github/workflows/deploy.yml（每次 push 自动构建部署）：

```yaml
name: Deploy Hugo site to Pages

on:
  push:
    branches: ["main"]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          submodules: recursive
      - uses: peaceiris/actions-hugo@v3
        with:
          extended: true
      - name: Build
        run: hugo --gc --minify
      - uses: actions/upload-pages-artifact@v3
        with:
          path: ./public

  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    needs: build
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

两个必须：`submodules: recursive`（主题是子模块，不拉取就构建失败）；`extended: true`（hugo-book 的 SCSS 需要）。

hugo.toml 里加一行（关键，别忘）：

```
baseURL = "https://790192412-ux.github.io/"
```

否则生成的页面链接指向错误地址。本地 `hugo server` 看不出问题，因为 server 会临时覆盖；部署后表现为"页面能打开但点啥都没反应"。

### 📤 首次推送

在站点根目录的 PowerShell 里执行：

```
git config --global user.name "你的GitHub用户名"
git config --global user.email "你注册用的邮箱"
git add -A
git commit -m "首次发布"
git branch -M main
git remote add origin https://github.com/你的用户名/你的用户名.github.io.git
git push -u origin main
```

push 时提示输入密码：GitHub 从 2021 年起不支持密码登录，需要 Personal Access Token：
1. 头像 → Settings → Developer settings → Personal access tokens → Tokens (classic)
2. Generate new token (classic)，有效期自选（90 天或 No expiration）
3. 勾选 repo 和 workflow 两个权限框——workflow 必须勾，否则推送 .github/workflows 文件会被拒绝
4. 复制 ghp_ 开头的字符串（只显示这一次，先存到记事本）
5. push 时 Username 填用户名，Password 粘贴 token

然后开启 Pages：仓库 → Settings → Pages → Source 选 "GitHub Actions" → Save。去 Actions 标签页看构建，绿色对勾即成功。之后浏览器打开 https://790192412-ux.github.io/ 验证。

我遇到的一个部署报错：仓库开启了"所有 Actions 必须用完整 SHA 锁定版本"的安全策略，@v4 这类版本号写法被拦。两种解法：
- 方案 A（推荐，省心）：Settings → Actions → General → 取消勾选 "Require actions to be pinned to a full-length commit SHA" → 回到失败的记录 Re-run
- 方案 B（保持开关）：把 deploy.yml 里的 @v4/@v3 换成对应仓库的完整 SHA（代价：以后升级 Action 要手动查新 SHA）

## 🔧 七、常见问题排查

> 说明：以下是我个人搭建过程中实际遇到的问题，仅供参考。每个人的环境不同，如果你在安装中遇到不一样的问题，可以使用"环境准备"里提到的方法——把报错信息描述给 AI，让它帮你定位排查。

### 📂 缺索引页

现象：`ERROR Site [0 0 0]: [en v1.0.0 guest]: Section 'docs' not found, check BookSection theme parameter`。

原因：主题首页要按 BookSection（默认 docs）渲染一个"栏目页"，但 content/docs/ 里没有 _index.md，Hugo 不认为它是合法 section。另一个常见诱因：Git 不跟踪空文件夹，推过代码再克隆后，docs/、posts/ 这些空文件夹会直接消失。

处理（三选一）：
- 保留 docs 结构：创建 content/docs/_index.md（title + weight + bookCollapseSection: true）
- 用 posts 做时间线博客：hugo.toml 里改 `BookSection = "posts"`，并创建 content/posts/_index.md
- 所有栏目都进侧边栏：`BookSection = "/"`

注意：hugo.toml 的 [params] 要在顶层，别误写进 [menu] 等别的块；自己手建 _index.md 时不要带 draft: true，否则分组页不渲染，会再撞上同一个报错。

### 🏠 首页空白

现象：hugo server -D 能跑，但首页只有一个搜索框。

原因：不是 bug。hugo-book 的首页显示的就是 docs/_index.md 的正文内容——只写了 front matter 没写正文，所以只剩搜索框和空侧边栏。

处理：给 docs/_index.md 加上正文（如欢迎语 + 板块链接列表），再建第一篇文章，刷新后侧边栏出现"文档"和文章，首页显示欢迎文字。

### ⛔ 推送被拒

现象：push 报 `! [rejected] main -> main (fetch first)`。

原因：本地和远程各自有新提交，最常见来源是曾在 GitHub 网页端编辑过文件——网页端每保存一次就是一个新提交，本地一推送就被拒。

处理：

```
git pull origin main --rebase
git push
```

如果出现 CONFLICT（两边改了同一个文件），打开冲突文件看 `<<<<<<<` / `=======` / `>>>>>>>` 标记，二选一保留。注意 rebase 中的名字是反的：--ours 是网页版，--theirs 是本地版。处理完收尾：

```
git add 冲突文件
git rebase --continue   # 若弹出 vim 编辑器，输入 :wq 回车
git push
```

搞不定可随时 `git rebase --abort` 完整回到之前状态，本地提交一个不少。

根治原则：网页端只读，绝不编辑；推送失败是网络问题就重试，别绕路去网页端改。

### 💥 部署失败

现象：push 成功但网站 404，或 Actions 红色。

排查顺序：
1. 仓库 Code 页有没有文件——没有说明 push 没成功，先解决 push
2. Actions 有没有记录——没有说明 workflow 文件位置不对（应在 .github/workflows/deploy.yml）；有红色就点进去看哪一步报错
3. Settings → Pages → Source 必须是 "GitHub Actions"（不是 "Deploy from a branch"）
4. 访问的网址必须精确是 https://用户名.github.io/，首次部署等 1~3 分钟，然后 Ctrl + F5 强刷

补充认知：`.git` 文件夹（本地账本）永远不会出现在 Code 页，这正常；要出现的是 `.github`（多了个 h），两者不是一回事。

### 🌐 连接重置

现象：`fatal: unable to access ... Recv failure: Connection was reset`。

原因：git 命令行默认不走系统代理。浏览器能开 GitHub，不代表 git 能连。解法二选一：
- 开梯子客户端的 TUN 模式（所有程序走代理；代价是网盘下载等流量也全走梯子，限额流量会很快见底）
- 只给 git 配代理（推荐）：梯子开着时查 HTTP 端口（可用 `reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" /v ProxyServer`，我查到的是 21081），然后：

```
git config --global http.https://github.com/.proxy http://127.0.0.1:21081
```

这条命令只让访问 github.com 走代理，其他程序一律直连。撤销：`git config --global --unset http.https://github.com/.proxy`。

## 🔁 八、日常维护

### 🖱️ 一键推送

日常更新就是三行：`git add -A` → `git commit -m "说明"` → `git push`。我把它封装成一个 bat 放在仓库根目录，双击即用：

```
@echo off
cd /d "%~dp0"
git add -A
git commit -m "更新"
git pull --rebase origin main
if errorlevel 1 pause & exit /b
git push
pause
```

说明：`cd /d "%~dp0"` 自动进入 bat 所在目录，换电脑、换路径都不用改脚本；中间两行是保险——推送前先把远程新提交拉下来叠好，拉取失败就停下等处理，不硬推。关键认知：git commit 是本地操作不需要网络，只有 git push 需要——所以平时可以只提交攒快照，挂梯子时再一次性推送。

### 📊 状态判断

git 状态总共四种，一张表记住：

| 状态 | 含义 | 动作 |
|---|---|---|
| up to date | 两边完全同步 | 什么都不用做 |
| ahead by N | 本地多 N 笔没推 | git push |
| behind by N | 远程多 N 笔没拉 | git pull |
| diverged（分叉） | 两边各有对方没有的提交 | git pull --rebase 再 git push |

"nothing to commit, working tree clean" 是正常提示（没有新改动需要记账），不是报错；真正要看的是 push 那一步有没有成功。推送失败时重试或挂梯子即可，提交不会丢——commit 的瞬间快照已经存在本地 .git 里。

### 🧪 最终验证

一套流程是否闭环，检查这几点：
- 浏览器打开 https://用户名.github.io/，首页、四个板块、文章都能访问
- 改一篇文章 → 双击 bat → 等 1~2 分钟 → 线上自动更新
- git status 显示 up to date
- 手机上也能打开且排版自适应（hugo-book 是响应式设计，可添加到主屏幕当 App 用）

### 💬 评论系统

Hugo 是纯静态站，评论都是接第三方服务。hugo-book 默认开启评论模板（BookComments = true），但默认是 Disqus——国内打不开，暂时不用管。以后想要：

### 🌍 域名与多站

- 自定义域名：GitHub Pages 设置里加 CNAME；但 baseURL 必须和最终域名一致，否则样式全挂
- 一个账号可开多个站点：用户站唯一，项目站每个仓库都能开（带子路径）
- 对个人博客更省事的做法：一个站用 Hugo 的 section 管多套内容（posts/、notes/、stories/），除非想要完全独立的域名和样式，才值得开第二个站

### 🖼️ 图片优化

文字极轻——一篇几千字的文章纯 HTML 也就 10~20KB，几百篇几十万字对加载速度几乎无感；图片才是重量级选手，一张手机直出照片 5~10MB 很常见。决定生死的不是图片数量，是图片体积。优化手段：压缩缩放、WebP/AVIF 格式、懒加载、Hugo 自带图片处理（构建时自动 resize 转格式）。以后想做图片密集的副站，可考虑 Cloudflare Pages——免费且流量不设限。

## 💡 十、方法论沉淀

### ❓ 先问需求

这次操作最核心的收获：先问需求，再选工具，不为工具找需求。搭博客前先想清楚"为什么不用现成平台""为什么需要自有内容"；选框架用排除法（需求 → 环境底线 → 折腾意愿），而不是被教程数量带偏。

### 📚 双账本模型

git 的本地仓库和远程仓库是两本各自记账的账本：push = 把本地新记录补到远程链的末尾，只有本地链完整包含远程链时才允许追加；两边各自加了新提交就分叉，git 拒绝推送——这是保护机制，不是错误。理解这个模型，git 的报错基本都能自己判断。

### 🔒 只读原则

网页端只读，绝不编辑。网页端每保存一次就是一个新提交，是分叉的最常见来源。所有修改在本地做；push 被拒就 `git pull --rebase` 再 `git push`，不要绕路。

### 🪶 轻量红利

静态站 + CDN 是业界标准玩法：轻量化保证加载快，CDN 保证就近取。这套思路不仅适用于博客——同一套 git 流程还顺带解决了 Obsidian 知识库的异地备份（私有仓库、一库一仓库、换电脑克隆即恢复），一次投入，多处受益。
