# OBS 画质优先录制指南

## 🎬 起因：同样的设置，三倍的体积

### 📊 一组异常数据

用同一套 OBS 设置录制两款游戏，文件体积差了三倍还多：

- 《寂静岭F》：4 小时不到 60G，约 15G/小时
- 《仁王3》DEMO：3 个多小时 150G+，约 50G/小时

当时的设置是 2K 分辨率、CQP=20。

### 🔍 问题的根源

起初怀疑是设置出了问题，排查后确认：这不是故障，而是 CQP 模式下的正常行为。理解这一点，是配置画质优先录制方案的前提。

## ⚙️ CQP：质量优先的码率控制

### 📐 恒定 QP 的原理

CQP（恒定量化参数）是一种质量优先的码率控制方式：

- 量化参数恒定，比特率不恒定
- 码率随画面复杂度自动波动
- QP 值越低，质量越高、文件越大

简单场景用低码率，复杂场景自动拉高码率，画质始终维持在同一水平。代价是文件大小无法提前预估，这是 CQP 与生俱来的特性。

### 🚫 排除 CBR/VBR

CBR（恒定比特率）与 VBR（可变比特率）都试过，结论是糊：

- CBR 固定数据量，复杂场景数据不够，画面直接糊
- VBR 可变但有上限，极端场景仍会牺牲质量

画质优先的选择是 CQP。QP 即量化参数，数值越低越清晰，录制常用范围在 18~22。

## 📈 画面复杂度决定体积

### 🧊 静态场景省码率

恐怖游戏场景阴暗、变化缓慢，编码器负担轻，码率自动走低——4 小时不到 60G 就是这么来的。

### 💥 动作场景吃码率

动作游戏快速镜头、粒子特效、高频战斗，几乎每帧都是高复杂度画面。《仁王3》这类游戏在 CQP=20 下码率可能飙到 80~120Mbps【此为推测】，3 小时 150G 属正常。

结论：文件大小差异先看画面复杂度，别急着怀疑设置。

## 🛠️ 方案选型

### 🖥️ 分辨率与 QP 值

- 录制分辨率匹配游戏原生分辨率，避免无意义的缩放
- 2K 原生场景：2K 录制 + 渲染时升频到 4K，兼顾体积与观感；4K 原生录制体积约为 2K 的 2.25 倍，硬件与存储压力大，不建议
- QP 值默认 20，画质与体积平衡良好；想再压缩可测试 21

### 🎞️ 编码器与剪辑兼容

H.265 同质量下能省约三到五成空间【此为推测】，但剪辑兼容性取决于达芬奇版本：

- 达芬奇专业版：可以使用 NVIDIA NVENC HEVC 编码（实际录出来是 H.265），可视情况选择
- 达芬奇普通版：解码功能可能被限制，H.265 素材可能无法正常使用

剪辑是长期工作，默认方案仍是 NVENC H.264，兼容性最稳。

### 💾 录制格式选 MKV

- 录制格式（Recording Format）选 Matroska Video（.mkv），防止录制突然中断导致文件损坏丢失
- 录制后需要使用素材时，用小丸工具箱封装即可
- 链路固定为：MKV → 小丸封装 → MP4 → 达芬奇

## 🎛️ 具体设置

除了下面几项，OBS 其他大多数设置保持默认即可。对画质起决定性影响的，还是 CQP（恒定 QP）及其相关设置。

### 📺 视频参数设置

- 基础/输出分辨率：与游戏原生一致（如 1920×1080 或 2560×1440）
- 帧率：60
- 缩放过滤：Lanczos（如需缩放时）

### 🧮 编码参数设置

- 编码器：NVIDIA NVENC H.264（达芬奇专业版可考虑 NVENC HEVC）
- 码率控制：CQP
- CQP 值：20（可测 21）
- 预设：最大质量
- 关键帧间隔：0（自动）
- 配置文件：high

### 🎧 音频参数设置

- 编码：AAC
- 比特率：192 kbps
- 采样率：48 kHz
- 声道：立体声

## 🧪 测试与调优

### 🔬 对比测试方法

选最具挑战性的场景（战斗、特效密集段），同场景用不同 CQP 各录 1 分钟：

1. 全屏播放对比画质
2. 对比文件大小
3. 重点观察快速运动区域、特效细节、纹理清晰度

### 🎯 微调 QP 值

每提高 1 个 QP，文件约减少 10%~15%【此为推测】。实测 CQP=20 到 21 的视觉差异在快速动作场景中几乎看不出来，但体积下降明显。测试通过即可定型，这是低风险、高回报的调整。

## ✂️ 分段录制

### 🧩 分段的意义

长录制必须分段：

- 单个文件损坏影响小
- 查找、备份、剪辑都方便
- 可选择性保留精彩片段

### ⏱️ 分段参数

- 对局制游戏：按局手动分段
- BOSS 战类游戏：按场分段（一场战斗大多 1~2 分钟，一个文件）
- 长流程游戏：自动分段兜底，按 4GB 大小或 30 分钟时长切分

## 🗄️ 存储与归档

### 📦 分级存储

画质优先意味着大文件，存储靠管理补：

- 热数据（当周项目）：主盘，录完即剪
- 温数据（近期复用）：中转盘
- 冷数据（成品与重要素材）：HDD 归档

### 🧹 盘内只存当前项目

录制盘只存当前项目，录完立刻转移，比无限加盘更治本。

## 🚀 发布环节

### 🏆 原画质优先

上传视频站时，只需要保证原画质优质即可。

### 😌 二压不必焦虑

现在平台的二压算法还不错，对画质的损失并不太大，不必为了应对二压而提前压缩素材或过度降低码率。

## 📝 沉淀的规则

### ✅ 七条录制规则

1. 文件大小差异先看画面复杂度，别急着怀疑设置
2. 质量优先选 CQP，清晰度恒定比体积可控重要
3. 录制分辨率匹配游戏原生分辨率
4. H.264 + MKV + 小丸 + 达芬奇链路不轻易换（达芬奇专业版可视情况用 HEVC）
5. 长录制必须分段
6. 存储分级管理，录制盘只留当前项目
7. 上传只需保证原画质优质，平台二压对画质损失不大
