# 🗂️ Obsidian 库 GitHub 备份完全指南

Hugo 博客上线后，顺手把 Obsidian 知识库的备份问题也解决了。我的情况是：多个 vault 分散在本地，日常库走 Obsidian 官方同步，几个低频但重要的库（模板库、英语积累库）一直没有可靠的备份手段。最后决定用 git 备份到 GitHub 私有仓库，这套方案跑通后沉淀成了可复用的流程，记录如下。

## 💭 为什么用 git 备份

##### ⚖️ 备份方案的取舍

先对比了几条路：网盘同步、iCloud、打包上传、git 备份。

- 网盘（百度网盘/坚果云）能做容灾备份，但没有版本历史，手滑删了内容找不回来；
- iCloud 同步我实际用过：文件数量少时还可以，多了之后开始出现**回档和重复**——Windows 版 iCloud 会生成 `(23)` 这类"幽灵冲突"副本，即使文件完全没被打开也会发生；多端同步时还会出现**插件配置互相覆盖**的冲突（`.obsidian` 里的配置文件在三端互相覆盖，需要不断清理）。推测 OneDrive 这类同步盘也是类似机制，问题应该差不多【此为推测】；
- 打包上传（zip 扔 GitHub）每次都要手动重传整个包，且 GitHub 本质是代码托管不是网盘，zip 只能放 Release 附件，失去版本历史；
- git 备份的核心价值是**每一次提交都是历史版本**，删了内容也能从历史里找回，而且私有仓库免费、不限数量。

结论：纯文本笔记库用 git 最合适。GitHub 仓库到 1GB 才提醒，单文件上限 100MB【此为 GitHub 官方限制】——我的库都是 10MB 以下的纯文本，英语库虽然有 2400+ 个小文件，但纯文本对 git 毫无压力。

##### 🛡️ 网盘的安全问题

网盘备份还有一个更大的问题——安全性。

- 国内网盘（以百度网盘为代表）有**自动审核机制**：文件上传后会被系统扫描分析（文件指纹、内容识别），用于执行版权和合规审查【搜索结论】；受《网络安全法》约束，需配合数据审查；
- 分享机制本身有泄露风险：百度云盘多次爆出**资源分享链接泄漏**事件，私人的东西可能被别人搜索到；
- iCloud 与 OneDrive 的情况稍好：没有百度那种内容审查，但默认是服务端加密（服务商持有密钥、技术上可访问内容），且受美国法律约束需配合法院令【搜索结论】；
- 对比之下，GitHub 私有仓库是"别人看不到"，纯文本笔记加本地 git 仓库，可控性更高。

结论：网盘适合存放的是完全不敏感的文件（公开资料、媒体素材），笔记、日记、个人思考这类内容，最稳妥的归宿还是 git 私有仓库。

##### 🗄️ 一库一仓库

多个 vault 的选择题：一个仓库装所有库，还是一库一仓库？

- Obsidian Git 插件按 vault 工作，要求 git 仓库就在 vault 根目录，一库一仓库天然契合，一个大仓库装所有库需要折腾"自定义路径"，容易出幺蛾子；
- 一库一仓库的版本历史各自独立，哪个坏了恢复哪个；`.gitignore` 每库按需配置；以后某个库想公开，直接改仓库可见性即可。

结论：一库一仓库最省心，流程每库重复一遍即可。

##### 🔍 适用条件判断

- 纯 Markdown 笔记 + 小图片（几 MB~几十 MB）→ 完美适合；
- 有单个超过 100MB 的文件（视频、大 PDF）→ GitHub 直接拒绝上传；
- 附件特别多（几百 MB 图片/PDF）→ 能备份但 git 会越来越慢，附件建议走网盘。

## 🧰 前置准备

##### ✅ 环境确认

- 安装 Git for Windows（[git-scm.com](https://git-scm.com) 下载，一路默认），装完 `git --version` 验证；
- 注册 GitHub 账号；
- 网络：commit 完全离线，只有 push 需要网络——这是后面备份节奏的基础。

##### 🗓️ 备份节奏规划

网络环境决定了节奏：不挂梯子时 GitHub 不稳定。所以规划成：

- 平时随便 commit（本地操作，不需要梯子，随时能回滚）；
- 挂 VPN 时一次性 push 所有库，一次会话全推完。

日常库继续走 Obsidian 官方同步（多设备实时、稳定），低频但有用的库走 git 冷备份。
>冷备份指的是平时用的不错，基本只用于存储防丢失的备份

## 🏗️ Github新建私有仓库

##### 🆕 建仓要点

在 GitHub 网页操作，每个库一个仓库：

1. 右上角 + → New repository；
2. Repository name 随便起（如 `Obsidian-TempleteVault`、`Obsidian-EnglishVault`）；
3. **必须选 Private**（笔记=隐私，别手滑选成 Public）；
4. **不要勾选** "Add a README file"、".gitignore"、"license"——建空仓库，否则后面 push 会冲突；
5. 点 Create repository。

> 如果建仓库时勾了 README，push 会报 `non-fast-forward`，最简单是删掉重建空仓库。

##### ✂️ 忽略清单编写

`.gitignore` 放在 **vault 根目录**，内容每个库通用，直接复制：

```
# Windows
Thumbs.db
desktop.ini

# Obsidian 工作区状态（每次开关都会变，无需备份）
.obsidian/workspace.json
.obsidian/workspace-mobile.json

# 回收站
.trash/
```

为什么忽略这些：`workspace.json` 是窗口布局缓存，每次打开都变，提交它会制造一堆垃圾提交；`.obsidian` 里的其他设置（快捷键、主题）建议保留提交，换电脑能一键恢复；`.trash` 是回收站。

## 🚀 本地初始化与首次推送

##### ⚙️ 初始化仓库

**关键：git 必须长在 vault 根目录里面**。我的模板库路径是`D:\02.Areas\ObsidianVaults\库模板`，vault 根目录是 `库模板` 这层，而 `Obsidian文档存放处` 是收纳箱层——**收纳箱层绝对不能 git init**，否则所有 vault 会被包进一个仓库。曾把 `.gitignore` 生成到收纳箱层，纠正成本很低，删掉重来即可。

在 vault 根目录执行（PowerShell）：

```
cd "D:\04.Archives\Obsidian文档存放处\库模板"
git init
git add .
git commit -m "first backup"
git branch -M main
git remote add origin https://github.com/你的用户名/Obsidian-TempleteVault.git
git push -u origin main
```

- `git init` 把当前目录变成 git 仓库；
- `git add .` 暂存所有文件（`.gitignore` 已排除杂项）；
- `git commit` 打本地快照；
- `git remote add origin` 绑定远程仓库地址，用户名照抄网页地址栏，写错会报 404。

##### 📤 首次推送

预计情况：首次 `git push` 会弹浏览器登录窗口，选浏览器登录你的 GitHub 账号，Git Credential Manager 会记住凭据，以后全自动。

- 文件多时首次推送会慢：英语库 2400+ 文件第一次 push 花了一两分钟，之后每次只传改动的几个文件，几秒钟搞定；
- 文件数多的库先加一行预防路径过长：`git config core.longpaths true`；
- 如果 remote 地址写错了占位符，用 `git remote set-url origin https://github.com/真实用户名/仓库名.git` 改掉再推。

## 📁 空文件夹的处理

##### 🕵️ 现象与原理

推上去后发现空文件夹没上传——只上传了有文件的文件夹（`.obsidian`、模板文件等），0~4 这几个空文件夹"消失"了。

原因：**git 只跟踪文件，不跟踪文件夹**，空文件夹在 git 眼里不存在，哪怕 `git add .` 也不会提交。

##### 📌 占位方案

- 方案 A：每个空文件夹放一个 `.gitkeep` 占位文件（最省事）；
- 方案 B：每个空文件夹写一篇 `说明.md`（推荐用于模板库）。

PowerShell 批量加 `.gitkeep`：

```
$folders = "0.📅日常记录 (Log)", "1.🚀短期项目 (Projects)", "2.🌐长期领域 (Areas)", "3.📚综合资源（Resources）", "4.📦历史归档（Archives）"
foreach ($f in $folders) { New-Item -ItemType File -Path "$f\.gitkeep" -Force | Out-Null }
```

然后重新提交推送：

```
git add .
git commit -m "add folder structure placeholder files"
git push
```

刷新 GitHub 页面，空文件夹就出现了。`.gitkeep` 是 git 社区约定俗成的占位名，git 本身不认它，纯占位用，不影响以后往里面放真文件。

##### 🎯 模板库一箭双雕

模板库是给别人（包括以后的自己）照着复制的，空文件夹光放着不知道放什么。所以给每个空文件夹写一篇说明文档（放什么的、命名规则是什么），一箭双雕：文件夹被 git 跟踪了，模板的使用说明书也有了。这个习惯固化进模板后，以后每个新 vault 都不会再被空文件夹问题吓到。

## ⚡ 日常备份与一键推送

##### 🔁 日常三连

日常备份就三行命令：

```
git add -A
git commit -m "更新"
git push
```

- `git add -A`：把所有改动（新增、修改、删除）纳入本次提交；
- `git commit -m "说明"`：打本地快照，**引号里的说明每次改成实际内容**（如 "update vocabulary notes"），三个月后翻历史才知道每个版本干了啥；
- `git push`：只有这步需要网络，VPN 只在最后这步挂着。

节奏是：平时只跑前两行，本地随时留快照零成本；挂 VPN 时补一行 push，把所有攒着的提交一次推上去。第一次推送后 `git push` 就能直接用（`-u origin main` 已绑定默认上游）。

`nothing to commit` 是正常提示不是报错，真正要关心的是 push 是否成功。

##### 📦 一键脚本封装

把三连封装成 `.bat`，放在仓库根目录（含 `.git` 的那层），双击即用。
新建记事本文档，复制进去，然后把后缀`.txt`改为`.bat`即可
**git推送-极简版**：
```
@echo off
cd /d "%~dp0"
git add -A
git commit -m "更新"
git push
pause

```

**git一键推送**：
```

@echo off
chcp 65001 >nul
title Git 一键提交并推送

rem 自动进入本文件所在的文件夹（仓库根目录），换电脑也不影响
cd /d "%~dp0"

echo 正在暂存所有改动...
git add -A
if errorlevel 1 goto :err

rem 检查是否有改动（有输出 = 有改动）
set "has=0"
for /f "delims=" %%i in ('git status --porcelain') do set "has=1"
if "%has%"=="0" (
    echo.
    echo 没有检测到任何改动，本次无需提交。
    pause
    exit /b 0
)

rem 输入提交说明，直接回车则使用默认的"更新"
set "msg=更新"
set /p "msg=提交说明（直接回车默认：更新）："
if "%msg%"=="" set "msg=更新"

echo 正在提交...
git commit -m "%msg%"
if errorlevel 1 goto :err

echo 正在推送（请确认 VPN 已连接）...
git push
if errorlevel 1 goto :err

echo.
echo ============ 提交并推送成功 ============
pause
exit /b 0

:err
echo.
echo ============ 出错了，请看上方红色报错信息 ============
pause
```

说明：

- `cd /d "%~dp0"` 自动定位到脚本所在目录，换电脑、换路径都不用改脚本；
- 无改动时提示"无需提交"直接退出；出错时窗口停住显示报错，方便排查；
- `.bat` 会被 `git add -A` 一起提交，换电脑克隆后自动跟着来——建议留着；
- 如果双击中文乱码：记事本另存为 ANSI 编码，并删掉第一行 `chcp 65001 >nul`；
- 嫌弹窗麻烦可用极简版：`cd /d "%~dp0"` + 三连 + `pause`。

##### 🧬 多库复制

每个新 vault 的流程：复制 `.gitignore` → `git init` → `add` → `commit` → 建 GitHub 仓库 → `push`，5 分钟一个。

- 复制：`Copy-Item "..\库模板\.gitignore" ".gitignore"`；
- 分两批：第一批本地操作（复制、init、commit，不需要 VPN）；第二批挂 VPN 时统一建仓、push；
- 把 `.gitignore` 内容存进模板库的一篇笔记里，以后开新库打开复制就行，不用翻对话记录。

## 🚚 换电脑与路径搬家

##### 💻 新机恢复流程

换电脑时，git 仓库一克隆全部原样回来：

1. 装好 git（官网下载一路 Next）；
2. 配置身份（新电脑必须做一次）：

```
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

3. 克隆仓库（VPN 挂着）：`git clone https://github.com/你的用户名/仓库名.git`（仓库主页 Code 按钮复制 HTTPS 地址）；
4. Obsidian → Open folder as vault → 选**包含 `.obsidian` 文件夹**的那一层；
5. 日常照旧三连，新电脑第一次记得先 `git pull` 拉最新。

插件和设置随 `.obsidian` 一起克隆过来（主题、快捷键、插件配置都在），插件偶尔需要在新电脑上重新启用一次。克隆前确保目标文件夹是空的。

##### 📂 路径搬家

vault 换路径（比如 D 盘 cut 到 E 盘）直接搬，什么都不用重新配置——`.git/` 装着全部提交历史和远程地址，`.obsidian/` 装着设置，都长在 vault 文件夹内部，跟着文件夹走。

正确姿势：

1. 先完全退出 Obsidian（跨盘移动本质是复制+删除，开着 Obsidian 可能复制一半或损坏）；
2. 正常剪切粘贴到新位置；
3. Obsidian 打开新路径文件夹。

搬完验证：`git remote -v` 还能看到 GitHub 地址、`git status` 工作区正常。外部脚本/快捷方式指着旧路径的要同步改。

##### 🧹 仓库清理

- 删除按钮不在仓库主页：Settings → 滚到最底部 Danger Zone → Delete this repository → 输仓库名确认（可能还要邮箱验证，防手滑设计）；
- 删除不可逆，普通用户无法自行恢复，删之前确认本地有留底；
- 暂时不用但以后可能要 → Archive（归档）更温和：变只读、不占心思、可反悔。

## 🩺 常见问题与排查

##### 🌐 网络与代理

现象：挂了梯子 push 仍报 `Connection was reset` 或 `Recv failure`。

原因：**git 命令行默认不认系统代理**，浏览器能上 GitHub 不代表 git 能上。

排查：

1. 确认 git 没配代理：`git config --global --get http.proxy`（输出为空=裸连被墙）；
2. 查代理端口（梯子开着时）：`reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" /v ProxyServer`（实测得到 `127.0.0.1:21081`）；
3. 只让 github.com 走代理（比 TUN 模式省流量，网盘下载等流量不受影响）：

```
git config --global http.https://github.com/.proxy http://127.0.0.1:21081
```

- 不想配代理就开 TUN 模式（所有程序走梯子，缺点吃资源、耗流量）；
- 报错对症：`Could not resolve host` → DNS 问题开 TUN；`Connection was reset` → 节点不稳换节点；`Failed to connect ... 443 Timed out` → 代理没生效按上面配；
- 撤销代理：`git config --global --unset http.proxy`（https 同理）。

##### ⚠️ 推送报错处理

| 现象 | 原因 | 处理 |
|---|---|---|
| `non-fast-forward` | 建仓库时勾了 README/LICENSE | 删库重建空仓库，或 `git pull origin main --allow-unrelated-histories` 后重推 |
| push 报 404 | 用户名/仓库名打错 | 回网页地址栏照抄 `/用户名/仓库名.git` |
| `Filename too long` | Windows 路径过长 | `git config core.longpaths true` 后重试 |
| `ahead by N commits` | 提交成功但没推上去 | 数据没丢，挂 VPN 补 push 即可 |

##### 🚫 隐私与红线

私有仓库也只是"别人看不到"，数据仍存在 GitHub服务器上——普通笔记无所谓，密码、身份证号等敏感内容别放。token 千万别写进任何笔记或提交进仓库。梯子和盗版资源链接这类内容，连私有仓库都不建议放，只留本地。

相比网盘的自动扫描与分享泄露风险，GitHub 私有仓库已经算是更可控的选择；但任何云端都不是"绝对保险"，真正敏感的私密内容（日记、账号信息）最稳妥的归宿仍是本地 + 离线备份。

## 💎 方法论沉淀

##### 📒 账本模型

对 git 最直观的理解是"两边各记各的账本"：本地和远程各有一条提交链，push 是把本地记录补到远程链末尾，只有本地完整包含远程时才允许追加；两边各自新增提交就分叉，需要先合并再推。这个模型能解释此前所有报错的来龙去脉。

##### 🧩 封装思维

`.bat` 的本质是把固定动作打包成可双击的入口。日常重复的三连、模板化的 `.gitignore`、每库一套的流程，都是"封装"——把容易忘、容易错的步骤变成固定的、可复制的东西。整条链路最终沉淀为：本地改 → 双击 bat → 挂 VPN 时集中推送 → 完成。

##### 🚨 内容红线

公开博客只放敢对任何人负责的内容，敏感链接留在 Obsidian 本地；发布前的标准是"粘贴进 content 目录的那一刻就等于公开"。这个意识要在做备份方案时就立好，而不是等出事了再补。
