# OBS 清晰录制指南：从 VBR 到 CQP

本文写于 2026 年 8 月，基于当前较为普遍的硬件水平与平台环境。录游戏最烦的事：画面一动起来就糊。翻 [OBS](https://obsproject.com/download) 教程，十有八九还在教"CBR 6000 码率"或"VBR `6000~9000`"，照着设完，改糊的还是糊，要不就是无脑拉高码率导致视频体积大得离谱。换到 CQP 模式才稳定清晰。本文直接给出可复现的 CQP 录制配置，再解释固定码率为何过时、CQP 的原理，并顺带说明为什么录不同游戏文件体积差异巨大。适用对象：用 OBS 录游戏、用达芬奇剪辑、对画质有要求的玩家。前置水平：会安装 OBS、了解基础录制流程即可。

## 🛠️ 第一阶段：配置与选型

### ⚙️ 一、CQP 设置

##### 🧩 编码器与格式

录制涉及三个独立的选择：编码器（怎么压缩）、录像格式（录制时存成什么）、封装格式（后期转成什么）。

- 编码器：通用场景选 NVIDIA NVENC H.264，剪映、达芬奇、平台通吃。达芬奇专业版用户可选用 NVENC HEVC——同画质下体积更小，但兼容性较差：HEVC 编码即使封装成 MP4，软件内识别的仍是 H.265（俗称 MP5），达芬奇目前只有专业版带相应解码器，免费版无法正常剪辑；剪映内部处理较多，倒是没有解码压力
- 录像格式：OBS 里"设置 → 输出 → 录像 → 录像格式"选 Matroska video（MKV），录制中断不会损坏文件
- 封装格式：录完用小丸工具箱封装转成 MP4，通用性最好，达芬奇、剪映、平台通吃

我的实际流程：MKV 录制 → 小丸工具箱封装转 MP4 → 达芬奇剪辑，既防中断又保兼容。预设选"最大质量"，关键帧间隔 0（自动）。

##### 🎚️ CQP 值定档

CQP 值越低越清晰、文件越大。从 CQP=20 起步，按游戏类型微调：
- **动作/射击**
	- 画面特点：快速运动、粒子特效密集
	- 推荐 CQP：`19~20`
- **RPG/剧情**
	- 画面特点：相对静态、UI 多、对话场景多
	- 推荐 CQP：`20~21`
- **2D/像素风**
	- 画面特点：大色块、边缘清晰、压缩效率高
	- 推荐 CQP：21

定档流程：先录 CQP=20 与 CQP=21 的同场景各 1 分钟对比，多数人看不出两档差异，但体积能省约两成【此为推测】。

我实测 CQP=21 后体感还行，遂定为主力参数。

##### 📐 分辨率与帧率

清晰度不只由 QP 决定，还有分辨率：

- 录制分辨率匹配游戏原生分辨率：
	- 游戏渲染多少就录多少，升采样没有信息增益，白占存储和编码资源
- 2K 录制 + 4K 渲染：
	- 主机/高分辨率场景的主力方案。
	- 录制 2K 控制体积与编码压力，达芬奇里升频输出 4K
		- 2K 升 4K 的放大损失小于 1080P 升 4K
- 1080P 参考：
	- 存储紧张或最终只输出 1080P 时，可临时降到 1080P 录制以减小体积

参数见下方清单

##### 📋 完整参数清单

2K 基准（主力）：

```
视频：基础分辨率 2560×1440 / 输出分辨率 2560×1440 / 帧率 60
色彩：NV12 / Rec.709 / 局部
编码器：NVIDIA NVENC H.264
码率控制：CQP，值 21
预设：最大质量
配置文件：high
关键帧间隔：0（自动）
B 帧：2
格式：MKV
音频：AAC 192kbps、48kHz、立体声
```

1080P 参考（减小体积用）：

```
视频：基础分辨率 1920×1080 / 输出分辨率 1920×1080 / 帧率 60
CQP 值：20 起步（相比 2K CQP=21 约省 `25%~30%` 空间【此为推测】）
其余与 2K 基准相同
```

### ⏳ 二、固定码率为何过时

##### 📜 固定码率的由来

早几年（大致 2016 至 2020 年）的 OBS 教程，录制设置几乎清一色是 CBR 6000 或 VBR `6000~9000`。这个数字不是随便拍的，它来自直播推流场景：当时 Twitch、YouTube、B 站对 1080P 推流的建议码率普遍在 6000Kbps 上下，教程作者直接把直播设置搬进了录制设置。在那个时代这样设也算合理——1080P 是主流分辨率，老显卡硬件编码质量一般，家庭上行带宽有限，固定码率既够用又省事。

##### 🌍 环境的变化

到了 2025 至 2026 年，环境完全变了：2K/4K 显示器与游戏普及，NVENC 硬件编码质量大幅提升，本地录制根本没有带宽限制。再用固定 `6000~9000` 码率录 1080P，简单场景浪费数据，复杂场景数据不够用——这就是照着老教程设置、激烈战斗时满屏马赛克的原因。我实际试过 CBR 和 VBR，结论是"都太糊了"。

## 🔬 第二阶段：理解原理

### 💡 三、CQP 是什么

##### 🧮 量化的原理

视频压缩的本质是丢弃人眼不敏感的信息。编码时，画面里每个像素的亮度本来是 `0~255` 共 256 个精确档位，编码器会按一定精度把它们归并成更少的档位——这个过程叫量化。可以理解为记账：精确到分的账目信息量大，只记到元的账目省空间但丢了精度。归并的粗细由量化步长（Qstep）决定：步长越大，归并越粗，丢的细节越多，文件越小；步长越小，精度越高，文件越大。档位太粗时，原本平滑的渐变会变成一条条色带，这就是常见的压缩痕迹。量化是视频压缩里最主要的信息损失来源。

##### 🔢 QP 值的含义

QP（Quantization Parameter，量化参数）就是量化步长的序号：H.264 里亮度 QP 取 `0~51`，QP=0 接近无损，QP=51 压缩到极致。所以：

- QP 越低 → 量化越精细 → 画质越好 → 文件越大
- QP 越高 → 细节丢失越多 → 画质越差 → 文件越小

常见范围 `18~28`，游戏录制通常用 `18~22`。经验上 QP 每提高 1，文件约减少 `10%~20%`【此为推测，不同画面差异很大】。

##### ⚖️ 三种码率控制

- CBR（恒定比特率）：无论画面简单复杂都用固定码率。简单场景浪费数据，复杂场景数据不够用，激烈战斗时就糊
- VBR（可变比特率）：码率可变但有上限，遇到极端复杂场景仍会牺牲质量
- CQP（恒定 QP）：保持 QP 恒定，即质量恒定，比特率随画面复杂度自动波动

| 模式 | 控制目标 | 质量表现 | 文件大小 |
| --- | --- | --- | --- |
| CBR | 固定比特率 | 复杂场景糊 | 恒定 |
| VBR | 限制比特率范围 | 极端场景糊 | 较恒定 |
| CQP | 固定质量 | 全程一致 | 随画面波动 |

一句话总结：CBR/VBR 是"码率先定、画质随缘"，CQP 是"画质先定、码率随需"。

## 🎬 第三阶段：实战与沉淀

### 💾 四、文件体积的控制

##### 📊 体积差异的来源

CQP 模式下，体积由画面复杂度决定，不随人的意愿变化。我最早意识到这一点，是发现同样设置（2K 60fps，NVENC H.264，CQP=20）录《寂静岭F》4 小时不到 60G，录《仁王3》DEMO 3 个多小时却超过 150G——同样"清晰"的设置，体积差三倍。这正是 CQP 的工作方式：恐怖游戏静态场景多，比特率自动压低；动作游戏画面变化快、战斗频率高、粒子特效密集，比特率被拉得很高。动作游戏高码率是"清晰"的代价，属正常现象，不是设置出了问题。

##### ✂️ 控制体积的手段

- 微调 CQP：21 不行就 22，画质下降很小，体积减少明显
- 自动分段：设置 → 输出 → 高级 → 录像，勾选"分段录制"，按大小 4000MB 或按时长 1800 秒分段，便于管理、备份与选择性保留；一局一局的游戏（如《星际2》合作）每局手动开始/停止，BOSS 战（如《仁王2》单场 `1~4` 分钟，大多 `1~2` 分钟）每场一个文件
- 存储与归档：录制盘只存当前项目，完成即归档到移动盘或大容量 HDD。文件生命周期管理比单纯加硬盘更重要

### 🚨 五、常见问题排查

| 现象       | 原因                        | 处理                   |
| -------- | ------------------------- | -------------------- |
| 文件大小差异巨大 | CQP 按画面复杂度分配码率，属正常行为      | 无需处理；想控制体积按上文手段调整    |
| 画面发糊     | CBR/VBR 固定或受限比特率在复杂场景数据不足 | 换回 CQP，质量恒定优先        |
| 硬盘告急     | 动作游戏整段长录制消耗极快             | 分段录制、CQP 上调 1 档、分级存储 |

### ✅ 六、画质验收

##### 🧪 对比测试方案

切换参数前先做小规模对比，用数据说话：

1. 选代表性场景（激烈战斗、特效密集、快速移动）
2. 用不同参数各录同一场景 1 分钟
3. 全屏播放对比：快速运动区域的边缘清晰度、粒子光影细节、纹理、色彩过渡
4. 最终输出 4K 的话，把各版本都渲染成 4K 再对比

##### 📈 编码压力监控

录制时观察 OBS 状态栏是否出现"编码过载"，任务管理器看 GPU 编码器占用；4K 60fps H.264 尤其容易丢帧，出现丢帧就降分辨率或提高 CQP。

##### ☁️ 平台二压与上传

录制阶段保证原画质优质即可，不必为上传过度压榨参数。现在视频平台的二压算法不错，上传 1080P/4K 后画质损失并不大，平台侧反而看重源文件本身的清晰度与码率。所以重心放在录制端：CQP 定档合理、分辨率匹配原生，上传时选择"原画"选项，剩下的交给平台。

### 🚀 七、进阶方向

##### 📺 4K 录制门槛

4K 素材像素是 2K 的 2.25 倍，文件约 `90~100GB/小时`【此为推测】，编码、存储、剪辑全线吃紧。当前维持 2K 方案，换电脑后再评估。

##### 🔄 编码器升级路线

短期维持 H.264；中期等达芬奇对 H.265 支持改善后切换（专业版可先行试用 NVENC HEVC）；长期关注 AV1 编码成熟度：

AV1 是新一代视频编码标准，同画质下压缩率比 H.265 更高、文件更小，但硬件编码支持和剪辑软件兼容性参差不齐，等生态成熟后再评估。换编码器前先小样测试剪辑兼容性。

### 🧠 八、方法论沉淀

##### ⭐ 质量优先原则

录制阶段画质恒定优先，体积服从内容复杂度；体积控制留给后期转码与输出阶段，不在录制时牺牲质量。

##### 🎯 原生匹配原则

游戏渲染多少就录多少。升采样没有信息增益，降采样损失细节，匹配原生分辨率才是清晰度的最优解。

##### 📏 先测后定原则

清晰度是主观感受，参数是数据问题。每次换游戏类型先做 1 分钟对比测试，用数据决定，不靠感觉。

##### 🧭 参数即权衡

QP 值、分辨率、帧率、编码器四者联动，不存在万能参数；理解 QP 的原理后，每个参数都能自己推算。
