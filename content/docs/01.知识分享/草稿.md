# Agent Skill 炼成与瘦身：渐进式披露原理与实操

> 类型：原理深挖｜说明：给出手上 skill 从"能用"到"扛得住长期加载"的分层思路，
> 含三层结构、归位判据与字数校验器。

引导段（H1 下、无标题，3~5 行）
- 解决什么问题：skill 用久了会膨胀，每次触发都偷吃大量tokens
- 做完能得到什么：一套分层判据 + 字数闸门 + 校验器
- 适用对象与前置水平

## 第一阶段：炼成与校验
- 承接早期那条路径；本阶段的落点是"发现少了一层"
### 已有的那套体系
- 交代起点：体系已经成型，为什么还值得回头校准
##### 从提示词到 skill
- 双链《从提示词到技能：一套自我迭代的 AI 工作流》
- 一句话带过，不重述
##### git 与迭代器
- skill-evolver 甚至是最先练成的 skill
- 版本回溯双通道 + skill-evolver 的角色
##### 自成体系的套组
- 四个组成部分各自是什么

### 反思与寻求校验
- 动机：原理了解不深，想用外来信息再校验一遍
	- 原理不深是因为直接让 agent 自己练成 skill
	- 等于说信息源只在 AI 本身
		- 虽然这种通用知识出错的可能性不大，而且自己也按经验做了修正
		- 但毕竟信息渠道有所限制，于是向外寻求对照验证
##### 外部探索
- 直接 B 站搜，找到一篇综合数据评价不错的
	- 附视频简介与关键数据（播放 / 藏率）
- 并直接交给自己要求练成的内容抓取 skill 来抓取分析
##### 内容概览
- 视频讲的三件事（背景与本质 / 渐进式披露 / Skill 与 MCP），先给个总览
##### 互相印证
- 哪些是我已经做到的
	- 规则固化与自动调用
- 哪些没提我也做到了
	- 自我迭代与统一管理
	- 按个人需求设计
- 哪些是应做 / 可以做、但我还没做的
	- 已有的都属"工程管理"层，缺的是"上下文成本"层

## 第二阶段：原理详解
- 把视频里那套原理讲清，作为后文判据的来源
### 三层结构
##### 元数据层
- 始终加载，等于目录
##### 指令层
- 命中才加载，一进就是全量
##### 资源层
- 按需中的按需
### reference 与 script
##### 读，还是跑
- 一个是读取进上下文，一个是执行不读
##### 成本两极分化
- reference 占 token / script 几乎为零；附"没写清怎么跑就会翻代码"这个坑

## 第三阶段：查漏补缺与回炉
- 一条连续动作：先用原理扫出问题、定下调子，再动手搬、装闸门
### 状态自查
- 从"学原理"切到"拿原理当尺子"
##### 实用性良好
- 拿三层结构逐格对照已有技能库
	- 基本符合，功能良好
##### 体积膨胀
- skill-evolver / xiaoxiao-xiuxian / personal-strategy
- 体积过大
	- 日志堆积 / 有多项可选规则 / 立了规则却不遵守
### 标准制定
##### skill 字数限制
- 从已有 skill 的数据中总结
- 软 10,000 / 硬 15,000 的由来
- 判据底座型 / 流程执行型，两档不同线
##### 专属知识库设计
- 一 skill 一库，互相隔离
	- 存相关文档
	- 运行缓存互相隔离
- 特殊情况有共享库
	- 内容提炼、文案拟定的通用核心
##### 内容拆分规则
- 决定一块内容留正文还是搬走
	- 在场判据：要不要在推导那一刻在场（作废结论的判例）
	- 分支判据：条件触发才用的，外置
	- 类型判据：按 skill 类型分流
##### 命名与索引
- 外置文件怎么命名、索引表怎么写
### 回炉重构
- 真正动手搬的一段
##### 留条件指针
- 搬走 ≠ 失联，正文原地留"条件 → 文件"映射
##### 外置与去重
- 外置 + 删双份漂移
##### 记账与备份
- 改前备份、改后记账
### 验收复盘
##### 校验脚本
- 设计了自查脚本，四条检查：字数 / 日志外置 / 版头 / 元数据
##### 复扫修正
- 校验器试出的误报（版头精确匹配）、二次复扫推翻的档位

## 总结
- 收束全篇；把这一轮的产物沉淀成往后每次都跑的东西
### 效果展示
##### Skill 瘦身完成
- 表格：各 skill 前后字数 + 降幅
##### 规则进一步完善
- 逐条列可复用判据
- 一条元规则：规则的执行者要与制定者分离
### 延伸思考
##### 交叉验证
- 不盲信单一信源（含 AI）；参考《AI 时代的信息判断原则》
##### 迭代机制的重要性
- 规则能长期维护，靠的是版本化 + 执行者与制定者分离
